## 账号与费用建议（待甲方确认）

- 生产云账号、域名和备案按甲方主体持有；开发方可引导注册、配置并通过独立 CAM 身份执行日常工作。开发方垫付须在甲方批准资源、金额上限、费用周期、支付方式、票据与报销规则后进行。甲方本人仍须完成平台规定的实名、核身与备案验证。
- 建议不采用“开发方实名持有生产账号，过段时间整体转交甲方”作为默认路径。腾讯云账号和资源归属取决于实名认证；企业转企业需满足满 30 天及双方核验。跨账号 CloudBase 环境不支持直接迁移。域名及备案须单独核定，不把换绑手机、邮箱视为主体交接。[账号归属](https://cloud.tencent.com/document/product/378/124852)、[变更企业主体](https://cloud.tencent.com/document/product/378/61028)、[CloudBase 跨账号迁移](https://cloud.tencent.com/document/faq/876/18438)
- 若开发方先用自己的环境做纯开发验证，后续应在甲方账号重新建生产环境并完成迁移与验证；不得把开发方环境的资源和业务数据描述为可以原样交接。
- 腾讯云企业专票抬头与账号实名主体一致；付款人与发票/报销安排应先由双方财务确认。CloudBase 从微信开发者工具购买的产品还有不同开票入口，实际订单渠道必须核对。[开票规则](https://cloud.tencent.com/document/product/555/7434)

## 最小采购范围与公开价预算

评估方向：上海地域、CloudBase MySQL 形态、Go API/常驻 worker 使用 Run、静态管理后台与传统云存储优先使用同一 CloudBase 体系。此为最小采购研究方向；内置 MySQL 的事务、备份恢复、主备切换及容量未完成真实验收，不能先承诺满足既定生产可靠性目标。[Run 说明](https://docs.cloudbase.net/run/introduction)、[MySQL 备份说明](https://docs.cloudbase.net/database/configuration/db/tdsql/backup)

| 项目 | 当前预算口径 | 采购前验证 |
| --- | --- | --- |
| 生产 CloudBase 环境 | 标准版公开价 **199 元/月**，含 330,000 资源点/月；这是候选基础套餐，不是最终容量承诺。 | 购买页地域、MySQL 形态、套餐权益、实际支付周期、备案资格、恢复能力。 |
| 极小测试环境 | 个人版公开活动价 **19.9 元/月**，含 40,000 资源点/月；与生产独立，不用免费体验环境作为长期生产资源。 | 活动价是否适用、测试数据隔离及最低容量。 |
| 公开基础月费小计 | **218.9 元/月**，仅为上述两个环境在活动价适用时的套餐价之和；不是含税包干价或实际账单。 | 正式购物车。超过套餐点数后，开启按量计费的费用另算。 |
| Run 常驻示例 | 1 核/2 GiB × 720 小时，按公开资源点单价为 **85.68 元等值资源消耗/月**。 | 实际实例规格、常驻实例数、扩容、出网与 HTTP 调用量；该 85.68 元优先从生产套餐点数扣，不能再机械加到 199 元上。 |
| MySQL 示例 | 假设平均 0.5 核持续计量 × 720 小时，为 **123.12 元等值资源消耗/月**；10 GB 存储示例为 **3.60 元等值资源消耗/月**。 | 实际最小算力/计量、备份、恢复和持续负载；示例不是承诺最低账单。 |
| 域名、DNS、证书、备案、固定出口、额外日志/NAT | 现无明确域名、配置和购物车，不填零价。 | 域名是否复用，证书类型，固定出口及 VPC/NAT 实际网络模式，日志保留，正式报价。 |

价格依据：[CloudBase 套餐与资源点价格](https://cloud.tencent.com/document/product/876/127357)。标准版 330,000 点与 1,000 点约 1 元是同一计费模型；环境内各项资源先消耗套餐点数，再按实际超限规则计费。Run 示例计算：`(0.055 + 2×0.032) × 720 = 85.68`；MySQL 示例计算：`0.342 × 0.5 × 720 = 123.12`。旧版 CU 配额和独立微信云托管价格不得混入。上述示例三项合计 212.40 元等值点数，小于标准版 330 元等值点数，但没有涵盖网关/流量/日志/其他用量，不能据此认定没有超额。

## 转为可付款采购单的门槛

1. 读回小程序关联账号和现有 CloudBase 环境状态，确认甲方主体与主账号保管方式。
2. 核定真实域名及备案状态；若需新购，使用甲方主体注册，取得域名候选与购物车价。
3. 在目标账号查看生产与测试环境的相同地域/套餐/周期购物车；确认资源点计费、超限、自动续费及预算上限。
4. 在目标环境验证 Run 常驻 worker、MySQL 事务与迁移、备份保留/时间点恢复及隔离恢复、对象存储权限、固定出口和公网回调。既定恢复与可用性要求不满足时，先给出单一替代资源方案与差额，不直接下单。
5. 由甲方确认采购/垫付和报销条款，再保存不含秘密的订单、实名、授权和费用回执。

在上述门槛完成前，只能向甲方发送“待确认事项和预算区间/假设”，不能发送为最终订单或承诺一次性零配合上线。
