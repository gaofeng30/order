# 设计与已确认约束

## 时间派生制作状态
只有持久状态 RESERVED 且取餐时间不晚于服务器当前时间加 30 分钟，读取时呈现 PREPARING；其他状态保持原值。制作开始时间不得早于 materialized_at。读取不写库、不递增版本；筛选与聚合在 SQL 内先应用规则，避免分页后过滤漏单。标记备好在锁行事务内校验门槛、补齐 preparing_at 并写 READY_FOR_PICKUP，保留幂等收据。

## 异常补偿：待平台验证，不得冒充已完成
周期为 30 分钟，仅真实异常待办才驱动重试，正常待支付不应高频查单。永久错误或人工待处理不无限自动重试；成功立即移出待办。保留正常支付/退款请求和回调。通知首次发送不能等待补偿周期。

单进程按需计时原型在 /tmp/order-background-scheduler-prototype；已证明空待办不建计时器，已知待办到期执行并在解决后停止。它没有多实例可靠唤醒，故没有接入运行代码。进程在提交异常记录后、发出唤醒前退出，或持有计时器的实例缩容，而其他实例已经进入空闲时，可能漏恢复。不能用这个原型替换现有补偿。

已核对 CloudBase 定时触发和 PostgreSQL CDC 官方路径。固定 cron 不满足无异常不循环查询；CDC 需要 publication、connector 授权与 RLS 实测，且存在复制 poller 的成本边界，不能未经测量宣称省钱。2026-10-14 16:28 北京时间 CloudRun detail 仍返回 resource isolated，尚不能核对目标运行条件或实测替代唤醒。因此暂不选择未经验证的新基础设施，不开通费用、不改 Prod。

### 三项重复调用修复

商户页按当前查询key和请求generation合并在途读取；新泳道与搜索不复用旧请求，隐藏使旧响应失效；手动刷新加入静默请求时保留可见失败反馈。PC点击行仅改高亮和详情，写入后仍走原刷新。对账日调度与异常重试分开，成功复用同环境、AppID、商户和账期的最新成功审计；拒绝记录不被历史成功遮蔽。单实例跨日异常不阻塞新日期。

此实现没有解决云平台可靠唤醒验证、停机跨账期恢复或首次多副本同时下载；上述限制属于当前阻断，不作为已满足发布条件。没有新增付费组件。
