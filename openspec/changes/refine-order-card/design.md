## 选定方案

### 删除而不是修正

「共 N 件」用户明确说不需要。既然要删，就把 `itemCount` 一起删掉，而不是先把 `b[1]` 改成 `b[2]` 再删模板 —— 留一个没人渲染的字段，下一个人会以为它有用途。

### 防线放在「聚合必须选数值列」

这个缺陷的成因不是手滑，是**元组下标在一次结构变更中整体右移，而所有基于下标的聚合都要跟着改**。当时改对了两处中的一处。

门禁因此断言一条结构规则：源码里对 `items` 的 `reduce` 聚合，其选取的下标必须落在数值列（`2` 数量 / `3` 原价 / `4` 折后价）。选到 `0`（id）或 `1`（名称）即报错。

这条规则比「断言 `itemCount` 等于 3」强，因为后者只锁住当前这一个字段，而前者锁住的是**这一类写法**：下次再有人写 `items.reduce((a, b) => a + b[1], 0)`，无论用在什么字段上都会被拦。

### 徽章去掉标签

`.oc-code` 本来是 `flex-direction: column`，装「号」+ 号码两行。去掉标签后不需要列方向，但保留它无害且改动更小 —— 单个子元素在列方向下同样居中。删掉 `.oc-code-lbl` 规则本身，避免留下无人使用的样式。

### 取消按钮不换行

`.oc-cancel` 在 flex 行里被压缩到四个字放不下。加 `white-space: nowrap` 与 `flex: 0 0 auto`：前者禁止折行，后者禁止被压缩 —— 只加前者，按钮仍会被压窄而让文字溢出。

## 边界

- 只改订单列表卡片。订单详情页的取餐码徽章是该页主视觉，不在本 change。
- 不改 `items` 元组本身，也不改任何数值。
- 不动商户端订单卡片：它的件数聚合（`it[2]`）本来就是对的。

## 会使旧验证失效的变更面

- `items` 元组的列序再次变化。
- 订单卡片重新引入基于 `items` 的聚合字段。
