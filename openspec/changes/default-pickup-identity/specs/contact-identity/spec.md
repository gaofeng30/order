# 默认取餐姓名与员工折扣契约

## MODIFIED Requirements

### Requirement: 姓名与两个号码之一匹配同一员工记录

员工身份 MUST 由账号已保存默认取餐姓名与主手机号或单个附加手机号共同判断；姓名 key 与任一号码命中同一条启用白名单才是员工。姓名按 NFKC 与 Unicode 去空白归一。未保存姓名、姓名不符或名单停用 MUST 按访客；本单临时联系人 MUST NOT 改变身份资料。

#### Scenario: 任一号码匹配
- WHEN 已保存姓名与主手机号或附加手机号同时匹配同一条启用记录
- THEN 身份投影、菜单展示价、Quote、发起支付及支付前复核采用员工身份；两种持久化运行路径一致。

#### Scenario: 仅号码匹配或跨记录拼接
- WHEN 仅号码匹配，或姓名与号码分别属于不同记录
- THEN 按访客处理，不公开其他记录信息；历史订单不回算。

### Requirement: 姓名与附加手机号独立保存

个人中心 MUST 在附加手机号上方提供默认取餐姓名；附加手机号 MUST 只提供号码输入。两项独立写入，只更新所提交字段，保存失败保留输入。默认姓名新写入必须非空、归一后不超过 64 UTF-8 字节。已有姓名原值保留，无数据清空或猜测回填。

#### Scenario: 默认姓名自动填充
- WHEN 用户已保存姓名并进入下单页
- THEN 自动填入联系人，允许临时修改；迟到的资料读取不得覆盖手工输入。

### Requirement: 本人号码与后台显示边界

本人鉴权的资料、确认页与本人订单详情 MUST 展示完整号码。商户/PC 订单与日志继续脱敏。PC 名单、编辑表单与导入页 MUST 明确两个号码共用同一默认姓名且须命中同一条启用记录。
