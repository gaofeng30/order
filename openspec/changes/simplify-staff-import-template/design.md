## Context

用户看过 §6.13.3 的七列模板后，明确只要姓名与手机号两个字段。

## Decisions

### 页面字段跟着模板一起收，而不是只收模板

用户此前定下的约束是「Excel 字段与前端页面一一对应」。若只把模板砍到两列而 §6.4 仍保留单位、部门、工号、备注，就会出现页面有字段、模板填不了的不对应状态——正是那条约束要避免的。

因此 §6.4 的可填字段同步收敛为两项。理由本身也成立：白名单的唯一职责是判定「这个手机号是不是员工」，单位与工号属人事系统，一期不在此维护。

### 状态留在页面，但不进模板

状态（启用 / 停用）不能删——§6.4 明确要求「停用保留记录但暂停折扣，用于离职人员」，这是真实运营需求。

但它不该进导入模板：停用是对**已有记录**的操作，不是新建时要填的数据。放进模板会让商户在表格里维护离职状态，而那件事在页面上点一下开关更直接。

因此定为：新增时默认启用，由页面开关切换，模板不含该列。

### 覆盖更新必须保留状态

这条是上一点的直接推论，但必须写死：如果导入按手机号覆盖时把状态一并重置为启用，那么商户每传一次全量表，所有已停用的离职人员都会被重新激活并恢复折扣。

因此明写「导入 MUST NOT 把已停用的记录重新启用」，与保留加入时间、累计消费、微信绑定关系并列。

### 未知列忽略而非报错

模板收到两列后，商户很可能沿用旧表（带单位、工号等）。若因多余列判定整份文件异常，等于强迫商户先手工删列。

因此定为按表头名匹配已知列、忽略未知列，并在预览中提示被忽略的列名——商户能看见发生了什么，但不被阻断。

## Risks / Trade-offs

| 风险 | 处置 |
| --- | --- |
| 删除单位/部门/工号后，商户失去在白名单里区分人员归属的手段 | 白名单不是人事系统。若后续确有需要，属独立范围新增 |
| 忽略未知列可能掩盖商户填错表头 | 预览会列出被忽略的列名；必填列缺失仍会中止整份文件 |

## Invalidation conditions

- 客户对员工白名单字段作出正式确认，要求保留归属信息；
- §6.13 全节因未取得客户确认而被否决。
