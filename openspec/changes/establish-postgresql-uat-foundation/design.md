# PostgreSQL persistence design

Status: UAT_SCOPE_CONFIRMED / READY_FOR_SOL; full sequencing and conditional asset gates: `.scratch/order-pg-uat-mvp/master-plan.md`.

Keep database/sql and the current service boundaries; use pgx stdlib with structured fields, explicit UTC session settings, verified TLS when requested, bounded pool and timeouts. No ambient PG credentials/DSN fallback. No server connection during Open.

Port SQL explicitly at each repository seam. Preserve unique payment/order/refund/idempotency constraints, snapshots, locks, cancellation/query/close semantics and fencing. PostgreSQL RETURNING replaces LastInsertId; ON CONFLICT targets are explicit; SQLSTATE classifies duplicate/deadlock/serialization errors. A failed transaction must be rolled back before retries, and unknown commit must not create a new external payment/refund intent.

The 44 ordered migrations retain version/name/checksum/dirty history and reject divergence. PG advisory locks use one checked-out connection; transactional DDL makes per-version schema/history changes atomic. The runner exclusively controls transaction boundaries; migration content cannot explicitly commit, roll back or otherwise escape its transaction. Uncertain lock acquisition as well as release failure/disconnect must discard the physical session instead of returning a potentially locked session to the pool. Readiness is read-only and fails on behind/dirty/mismatched/too-new history and missing/incompatible required business tables, columns and key unique/FK/CHECK constraints. Maintain an explicit bounded contract manifest derived from the migrations and repository use; no business-row scan or general-purpose whole-database diff. At minimum prove missing orders and missing uq_orders_prepayment are rejected.

Initially one process shares the HTTP and worker pool, maximum open 10; UAT replica count is not chosen until its total budget is verified (including rolling old/new overlap, other clients, migration and reserve). Saturation tests report wait and timeout behavior.

Tests use only an ephemeral local PG cluster with loopback/SCRAM or a restricted Unix socket, an empty synthetic DB, explicit environment allowlist and bounded cleanup. Local PG16 common-subset tests do not prove CloudBase17 transport/permissions or live platform behavior. No existing PG/MySQL/CloudBase database is connected.

Writer evidence: OpenSpec strict validation; focused RGR per seam; gofmt/test/race/vet/build and backend smoke appropriate to isolated config; real PG migration/transaction/concurrency/recovery faults; owned diff and sensitive-data checks. The eight existing governance files were separately saved as authorized local snapshot affb06cafeac5a922b7f436837337eeae7e7079a, not a candidate. On closeout, the 457 owned source files were transferred with exact SHA256 checks into the dedicated worktree; the two protected research originals and former index/worktree remain untouched. No research file is included in the backend candidate; no reset, ignore workaround or gate override is used.

Image confirmation receipts are immutable and globally reusable. Product and launch-layer commands read those facts before reserving their transaction connection, while retaining the owner lock, receipt replay and error handling inside the transaction. This prevents a nested pool acquisition under the shared ten-connection budget. Payment reconciliation retains its batch due cutoff, but each query lease uses the live service clock after acquiring the prepayment row lock, including retries; expired provider results still fail closed.

After Writer Gate passes, form a local candidate and obtain independent read-only exact-SHA verification in a clean detached worktree; another independent contract/run review is required for high-risk financial/UAT claims. Changed source/spec/tasks/config invalidates prior verification. Main merge/push is not authorized. Roll back the isolated candidate/schema only in the disposable test DB; production recovery is planning only.

PG columns that formerly held unsigned bigint use NUMERIC(20,0) with exact 0..18446744073709551615 checks, retaining amount/counter/storage bounds and matching all FK types. Auto-generated IDs use an owned native bigint sequence as the default for the numeric column; generated sequence values are limited by PG's signed bigint sequence range, while explicit stored IDs retain unsigned bounds. No existing production data conversion is authorized; any future migration must verify existing IDs and sequence headroom. Runtime uint64 encoding/scan/overflow checks are observed in the local PG16 draft receipts; actual target PG17 behavior remains unverified.

The existing per-business-date pickup_sequences counter is not replaced by ordinary PostgreSQL auto-ID sequences: allocation and order creation remain one transaction, duplicates reuse the same number, failed transactions do not burn a number, and 9999 fails closed. Local PG16 draft tests now cover these runtime invariants, TLS negative cases, migration faults, uint64 codecs, historical backfills and business SQL; their scope and source hashes are in execution-checkpoints.md. They do not prove target CloudBase17 permissions, deployed financial processes, independent exact-SHA verification or real-platform acceptance.
