## Context

新增阶段第二件，也是最后一件能纯前端做完的。后续的全局折扣率、手机号绑定、订阅消息、退款、支付对账、扫码登录都依赖后端，而 `services/api` 目前只有 catalog。

## Goals / Non-Goals

**Goals**

- 两端的预约模型与生效 spec 的「离散取餐时间点 + 按餐段固定截单」一致。
- 取餐时间只在一处选定，结算页不再重复提供选择器。
- 修复上一 change 遗留的 `type` 字段读取点。

**Non-Goals**

- 不实现按餐段过滤商品（需后端扩展商品 schema）。
- 不实现服务端定时排产与自动截单。

## Decisions

### 时间点由范围与粒度推导，不写死数组

原实现是 `RESERVE_SLOTS = ['11:30','12:00',...]` 一条写死的数组，与餐段无关。spec 要求粒度商户可配，写死数组无法满足。

改为 `pickupTimes(periodKey)` 由该餐段的 `from`/`to` 与 `PICKUP_STEP_MIN` 推导。门禁断言的是推导结果而非常量内容——粒度改成 15 时时间点数量必须随之变化，这条在 PC 侧的 UI1 里实测过。

### 取餐时间选一次，结算页只读

原实现在结算页选日期和时段。但菜单是按取餐时间所属餐段过滤商品的（该过滤本轮因后端限制未实现，但模型必须先对），所以时间必须在**进菜单之前或菜单顶部**确定，否则用户会先挑完菜才发现所选餐段没有这些菜。

因此取餐时间放在菜单顶部条，存在 `globalData.pickup` 跨页共享，结算页只读展示 + 一个回菜单的修改入口。结算页原有的日期段与时段横滑控件整体删除。

### 已截餐段整组折叠，而不是逐条置灰

一个餐段有 5 个时间点。全部截单时逐条渲染灰项，用户要读 5 遍才明白是整顿没了；而且屏幕上灰的比亮的多。

折叠成一行「午餐 · 已截单 · 11:30 截止」既说明了原因，也暴露了截止时刻——用户下次知道该几点前下单。门禁断言折叠组的 `times` 必须为空数组，防止有人"顺手"把它改回逐条渲染。

### 按餐段过滤商品是本轮的硬边界

spec 要求菜单只展示所选取餐时间所属餐段可售的商品，PRD §6.3 也要求商品有「全天 / 仅午餐 / 仅晚餐」字段。但商品来自 API，`catalogStore` 的契约里没有这个字段，服务端不下发。

前端无法凭空造出这个维度。硬做只能靠本地 mock 覆盖服务端数据——那正是 `miniprogram-menu-catalog` 明令禁止的。因此声明为非目标，等后端扩展商品 schema。

### 顺带修上一 change 的三处遗留

`adopt-six-state-order-lifecycle` 删了订单 `type` 字段，但三处读取点没清：`canCancelReserve` 判 `o.type === 'reserve'`（导致取消按钮永远不出现）、`result.js` 按 `type` 分支渲染、`order-detail.wxml` 绑定已被删除的 `reserve` 字段。

前两处是功能性回归，第三处渲染的是错误分支。都在本 change 的语义范围内（取消规则与取餐展示），一并修复，并补了两条通用断言：全端不得读 `o.type`、模板不得绑定页面从未设置的字段。后者是把「删了 data 忘了删模板」这类问题变成可执行检查。

## Risks / Trade-offs

| 风险 | 处置 |
| --- | --- |
| 菜单不按餐段过滤商品，用户可能点到该餐段不供应的菜 | 后端限制，已声明为非目标并写入 spec delta 的边界。后端扩展商品 schema 后需补一个 change |
| `NOW_MINS` 是演示时钟常量，截单判定随之固定 | 原型固有约束。真实实现由服务端按门店时区计算，`isPeriodCutOff` 的签名已经与之兼容 |
| PC 设置改为按餐段后，旧的 `openTime`/`closeTime` 消失 | 一期没有「营业起止时间」这个业务概念——营业状态由三段开关承担，接单窗口由餐段截单承担。移除是收敛而非丢功能 |
| 取餐时间条只在菜单页，首页无此入口 | PRD §5.1 定义的首页不含取餐信息。用户从首页「预约点餐」进菜单即看到顶部条 |

## Invalidation conditions

- 客户对可预约天数、餐段数量或截单规则作出新的正式确认；
- 后端扩展商品契约加入餐段字段，届时需补按餐段过滤菜单的 change；
- `mvp-product-baseline` 的取餐时间 requirement 被其他 change 修改。
