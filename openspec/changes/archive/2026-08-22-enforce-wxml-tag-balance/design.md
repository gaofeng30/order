## 选定方案

### 复用已有的栈，不新写解析器

`lint_wx.py` 里已经有：

```python
TAG = re.compile(r'<([a-zA-Z][\w-]*)((?:[^<>"\']|"[^"]*"|\'[^\']*\')*?)(/?)>|</([a-zA-Z][\w-]*)>', re.S)
stack = [None]          # 每层记录该层上一个兄弟的条件类型
```

这个正则**已经正确处理了属性值里的 `>`**（`"[^"]*"` 分支），而这正是天真实现最容易踩的坑 —— 我在探查阶段先写了个不带引号跟踪的版本，立刻在 `wx:if="{{qty > 0}}"` 上报出四个假阳性。既有正则是对的，重写只会把这个坑再踩一遍。

栈也已经在维护，只是每层存的是「上一个兄弟的条件类型」而不是标签名。改为存 `(cond, name, line)` 三元组，弹出时比对名字即可。这样两项检查共用一次遍历，且 `wx:elif` 的既有行为完全不变。

### 三类错误分别报，不合并成一句

```
孤立 </view>                              栈已空却出现闭合标签
</view> 与第 22 行的 <scroll-view> 不匹配   栈顶名字对不上
<view> 未闭合                              文件结束栈非空
```

合并成「标签不配平」会把定位信息丢掉。上面那个 profile 的例子里，开发者工具只能指到第 50 行（错误暴露的位置），而真正该删的是第 46 行；三类分报加上「与第 N 行的 X 不匹配」才能把人直接带到成对的另一端。

### void 元素清单与既有实现保持一致

既有 `wx:elif` 检查用的是 `('image', 'input', 'icon', 'br')`。标签配对沿用同一份清单，不各自维护 —— 两份清单迟早会漂移，届时同一个文件在两项检查里会被解析成不同的树。

## 边界

- 只做标签配对。属性合法性、表达式语法、组件是否在 `usingComponents` 里注册，都不在本 change。
- 不改 profile 页的内容：那页还有一个与 §5.9 冲突的「外卖配送」入口，属独立范围问题。
- 不引入外部依赖：`lint_wx.py` 目前零依赖，保持。

## 会使旧验证失效的变更面

- `TAG` 正则的引号处理被改动。
- void 元素清单在两项检查间产生分歧。
- 层级栈被拆成两个各自遍历。
