## Context

本 change 是删除类三件套的第二件，前一件 `remove-member-coupon-capability` 已集成。两者共享 `apps/wechat-miniprogram/**`，因此串行。

实施中撞到一个规划阶段没预见的问题：**生效 spec 之间已经不一致**。`miniprogram-menu-catalog`（2026-08-13）要求首页必须渲染招牌位，而 2026-08-19 客户评审记录（第 1 顺位证据）说「都删掉」。这不是本 change 制造的冲突，是它暴露的。

## Goals / Non-Goals

**Goals**

- 让小程序端不再暴露品牌选择页、商户端工作台与首页营销位。
- 让商户 TabBar 符合评审 §38 的三格约束，同时不把商户中心删成孤儿页。
- 把 `miniprogram-menu-catalog` 中与客户评审冲突的条款一并修订。

**Non-Goals**

- 不删「到店点单」入口。
- 不删商户端的营业设置、开屏图层与分类管理。
- 不动 PC 后台。

## Decisions

### 首页彻底不碰 catalog，而不是只删招牌卡

删掉今日招牌后，`listState`、`retryCatalog` 与 `signature` 只剩空转。0818 PRD §5.1 定义的首页内容是门店信息、营业状态、门店公告与三个入口，没有商品位。因此把 catalog 请求整个从首页移除，而不是留一个不展示结果的请求。

这要求同步修订 `miniprogram-menu-catalog`：list 状态与 retry 义务收敛到菜单，首页明确 `MUST NOT` 请求 catalog。菜单侧的义务**一条未减**——原 requirement 对 loading/empty/error/ready、retry 必须发新请求、error/empty 不得显示 mock、不得携带假 ID 的全部约束都原样保留，只是主语从「首页与菜单」变成「菜单」。

### 为什么把 spec delta 放进本 change 而不是单开

前面 `realign-mvp-product-baseline` 是独立的 spec change，因为它要对齐的是整份产品基线，与任何具体代码删除无关。这里不同：`miniprogram-menu-catalog` 的这一条修订**只为允许本次删除而存在**，两者不可分别验收——单改 spec 会让 spec 描述一个仍然存在的东西，单删代码会违反 spec。因此合为一个 change，验收判据仍是单一的。

### TabBar 收敛必须同时解决可达性

评审 §38 只说底部保留三格。但 `admin-profile` 当前只能从 TabBar 的「我的」进入，而它承载着营业设置、开屏图层、分类管理与切换身份。直接砍到三格会让这四条路径全部不可达——那不是删除，是打断。

因此在订单页导航栏右侧补一个「商户中心」入口。这是删除动作的**最小补偿控件**，不是新功能：它恢复的是本来就存在的可达性。0818 PRD §6.10 已经规定订单页右上角承载返回身份选择的入口，与此不冲突（切换身份仍在商户中心内）。

不选择「一并删除 admin-profile 及其下属页」，因为那属于「商户端功能迁 PC」，而且 0818 PRD §16.3 P1「营业状态切换归属哪一端」尚未拍板，删掉会强行替客户做决定。

### 失效引用必须当作 bug 修，不是顺手优化

删除页面后，两处引用指向了不存在的目标：身份选择页的商户端入口指向 `admin-dashboard`，开屏图层编辑页以品牌页为预览底图之一。前者会让商户点进去直接断路。

这两处不是「相邻问题」——它们是本次删除**直接造成**的破坏，修复属于本 change 的范围。UI1 用例为两者各加了一条断言，防止回归。

### UI1 断言写成缺失断言加可达性断言

删除类改动的两个典型失败模式：删了一半（页面没了但路由还在），和删过头（把还需要的路径一起打断）。因此断言分两类：逐项指名的缺失断言（路由、目录、脚本 token、模板片段、种子导出），加上可达性断言（商户中心仍可达、身份选择页指向存在的页面、菜单 catalog 链路完好）。

## Risks / Trade-offs

| 风险 | 处置 |
| --- | --- |
| 首页不再请求 catalog，冷启动后菜单首次进入才拉目录 | 这是 PRD §5.1 定义的首页形态的必然结果。菜单自身的 `onShow` 请求与 retry 链路未变，UI1 覆盖 |
| 「到店点单」入口留在首页，而即时单已被客户删除 | 该入口的删除与确认页取餐方式切换、订单 `type` 字段和状态机同属即时单删除，拆开会留下「入口没了但能力还在」的假象。本 change 明确声明为非目标 |
| 商户中心入口从 TabBar 移到订单页导航栏，商户需重新习惯 | 评审 §38 的三格是硬约束。导航栏右侧是现场高频页面上最不占地方的位置 |
| `miniprogram-menu-catalog` 的修订影响其他依赖该 spec 的 change | 该 spec 的菜单、详情、购物车与 harness 四条 requirement 均未改动，只有首页部分收敛 |

## Invalidation conditions

- 客户对首页内容或商户端底部导航作出新的正式确认；
- `miniprogram-menu-catalog` 被其他 change 修改，导致 MODIFIED 标题不再匹配；
- 0818 PRD §16.3 P1（营业状态切换归属）拍板后要求删除 `admin-profile`，此时本 change 补的商户中心入口需一并重新评估。
