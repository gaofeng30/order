# Brainstorming

## 不适用

需求已唯一确定且只需执行时，不要强行脑暴拖延。

## 流程

1. **澄清约束**：预算/时间/兼容性/团队熟悉度等（缺失则先问最小集合）。
2. **发散**：至少 **2–3** 个实质不同方案，避免假选项（仅措辞不同）。
3. **准则**：3–5 条可打分维度，如复杂度、风险、可维护性、上线成本。
4. **权衡表**：短表或列表，标出各方案相对优劣，**不隐藏已知缺点**。
5. **推荐**：给一个首选并说明假设；若假设错，备选是谁。

## 输出格式

- 先给**结论与推荐**一段，再给支撑与备选（方便 busy reader）。
- 不做无依据排名；不确定处标明需验证（spike/实验）。

## 与规划协作

选定方案后，重大落地应交给 `planning-with-files` 写入计划再继续编码。
