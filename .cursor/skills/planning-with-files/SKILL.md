# Planning With Files

## 原则

计划**落在文件里**可追溯，而不是只存在于聊天上下文。聊天用于讨论，文件用于承诺与对齐。

## 建议工件（按项目选用，勿堆砌）

| 工件 | 用途 |
|------|------|
| `docs/plans/YYYY-MM-短名.md` 或 `PLAN.md` | 目标、非目标、方案对比、风险 |
| 检查清单 | 可勾选的步骤 + 每步验证方式 |
| 与 issue/PR 的链接 | 若团队用工单，文件顶部注明编号 |

## 推荐结构

1. **背景与目标**：成功长什么样（可验证）。
2. **非目标**：本次不做的事情，防范围蔓延。
3. **方案**：可选 2–3 个，每个写**权衡**（复杂度、风险、回滚）。
4. **步骤与验证**：`步骤 → verify`，与 Karpathy「目标驱动」一致。
5. **回滚/开关**：若适用，写如何撤销。

## 执行约定

- 计划通过后再大规模改代码；执行中若发现计划错误，**先改计划文件**再改代码。
- 单会话装不下时拆里程碑：每个里程碑有可运行的 verify。
