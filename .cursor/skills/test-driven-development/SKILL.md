# Test-Driven Development

## 核心循环

1. **红**：写**一个**小而真的失败断言（或的最小复现）。
2. **绿**：写**最少**代码让其通过；不夹带无关功能。
3. **重构**：在保持全绿的前提下整理结构；不扩大行为面。

## 粒度

- 测试名即规格：读测试应像读需求。
- 先覆盖当前 bug/功能路径，再谈覆盖率虚荣指标。

## 与项目交互

- 遵守仓库测试框架与目录惯例；不发明并行测试体系。
- 无法测的边界（时间、随机、IO）用分层：可测逻辑下沉，边界用替身/接口。

## 停手条件

全绿且验收目标满足即停；避免「再写两个锦上添花」的测试膨胀，除非用户要求。
