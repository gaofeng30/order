# 在线点单系统开发服务合同草案

> 本文为商务沟通和合同起草草案，不构成法律意见。正式签署前，建议由具备资质的法律或财税专业人士审核。

## 一、合同定位

本合同建议定位为“第一期在线点单系统 MVP 定制开发服务合同”。

第一期目标是为甲方交付一套可上线使用的微信小程序在线点单系统，覆盖用户点单、微信支付、线下自提、商户后台管理、订单核销和基础经营数据看板。

第一期不定位为完整外卖平台、多商户平台、连锁门店系统或长期代运营服务。后续如需扩展外卖、多门店、多档口、会员、优惠券、发票、企业月结、第三方系统对接等功能，双方另行确认需求、工期和费用。

## 三、服务范围

### 3.1 用户端微信小程序

乙方负责开发用户端微信小程序，首期包含：

- 首页和门店基础信息展示。
- 菜品分类和菜品列表。
- 菜品详情、价格、图片、售罄状态展示。
- 购物车。
- 提交订单。
- 微信登录或手机号授权。
- 微信支付接入。
- 订单列表和订单详情。
- 订单号和二维码取餐凭证。
- 基础订单状态展示。
- 外卖入口可做 UI 预留，但明确标记“暂未开放”。

### 3.2 商户管理后台

乙方负责开发商户 Admin 后台，首期包含：

- 后台登录。
- 商品分类管理。
- 商品管理。
- 商品图片上传。
- 商品价格、上下架、售罄状态管理。
- 订单列表和订单详情。
- 扫码核销和手动核销。
- 基础数据看板。
- 营业时间和公告配置。
- 基础后台权限控制。

### 3.3 后端与系统能力

乙方负责开发后端服务和基础系统能力，首期包含：

- API 服务。
- 数据库设计与实现。
- 用户、商品、分类、订单、支付、核销等核心数据模型。
- 订单编号和取餐码生成。
- 支付状态记录。
- 异常订单记录。
- 操作日志。
- 基础数据备份方案。
- 生产环境部署协助。

### 3.4 微信支付与上线协助

乙方负责提供技术接入和配置协助，包含：

- 微信小程序开发配置协助。
- 微信支付商户号接入协助。
- 支付回调配置。
- 域名、HTTPS、服务器部署配置协助。
- 小程序提审和上线协助。

微信小程序账号、微信支付商户号、云账号、域名、备案主体和收款账户应归甲方所有。乙方不建议使用乙方个人主体长期代持甲方生产系统资产。

## 四、首期不包含范围

本合同首期不包含以下内容：

- 平台型外卖。
- 多商户入驻。
- 多门店、多食堂、多档口复杂权限。
- 配送地址、配送费、配送范围。
- 会员体系、优惠券、积分、储值卡、预付卡。
- 发票、企业月结、复杂财务分账。
- 排队叫号屏、打印机、硬件设备对接。
- 第三方 ERP、财务系统、食堂系统对接。
- 订阅号、服务号的复杂运营和消息推送体系。
- 直播、社区、评价广场、营销裂变等高审核风险功能。
- 甲方日常代运营服务。
- 大规模 UI 重做、品牌 VI 设计、宣传海报设计。

上述功能如甲方后续需要，双方应另行签署补充协议或需求变更单。

## 七、质保与运维

### 7.1 全年免费质保

乙方赠送上线后 `12 个月免费 bug 质保`。

免费质保范围：

- 修复已验收功能中由乙方代码原因导致的程序 bug。
- 修复已交付范围内的下单、支付状态、订单、核销、后台管理等功能异常。
- 对已交付功能提供必要的问题排查和修复。

免费质保不包含：

- 新增功能。
- 已验收页面的大幅重做。
- 甲方业务规则变化导致的改造。
- 第三方平台政策、接口、审核规则变化导致的改造。
- 商品上下架、活动配置、图片处理、文案修改等日常运营工作。
- 甲方账号、服务器、域名、备案、支付商户号自身问题导致的处理成本。
- 非乙方原因导致的数据误删、账号权限误操作或第三方服务不可用。

### 7.2 赠送三个月基础运维

乙方赠送上线后 `3 个月基础运维服务`。

基础运维包含：

- 上线初期系统观察。
- 基础服务器状态检查。
- 小程序后台、云资源、支付配置协助。
- 简单操作答疑。
- 线上故障协助排查。

基础运维不包含日常代运营、固定专员驻场、7×24 小时人工值守、美工制作、批量商品维护和持续活动配置。

### 7.3 标准运维服务

三个月赠送期结束后，如甲方需要持续运维、专员协助、商品上下架、活动配置、简单美工支持等服务，双方可另行签署标准运维服务协议。

建议标准运维服务费：人民币 `12000 元/年`。

标准运维可包含：

- 工作日技术支持。
- 线上故障响应。
- 已交付功能 bug 修复。
- 每月不超过 `4 小时` 的后台操作协助。
- 商品上下架、简单活动配置、基础文案修改。
- 基础服务器和证书续期提醒。

超出服务范围或服务时长的事项，建议按以下方式另行计费：

- 一般技术支持：`200-300 元/小时`。
- 功能迭代开发：`1000-1500 元/人天`。
- 简单美工图处理：`100-300 元/张`。
- 新页面设计：`500-1500 元/页`。

如甲方要求 `24 小时 on call`，建议仅限严重生产故障，例如系统不可访问、无法下单、支付异常、订单无法核销等 P0/P1 问题。商品上下架、图片处理、活动配置、文案修改等运营类事项应按工作时间处理。

## 十、验收标准

项目验收建议以第一期确认的功能清单为准。

MVP 验收至少满足：

- 用户可以在微信小程序完成浏览、加入购物车、提交订单。
- 用户可以完成微信支付或按约定方式完成支付流程测试。
- 用户可以在订单详情看到订单号和二维码。
- 商户后台可以维护商品、价格、图片、上下架和售罄状态。
- 商户后台可以查看订单并完成扫码或手动核销。
- 系统可以正确处理基础订单状态变化。
- 数据看板可以展示今日营收、订单数和基础销量数据。
- 关键操作有日志，异常订单可追踪。

甲方应在乙方提交验收版本后 `7 个工作日` 内完成验收并反馈问题。若甲方未在期限内提出书面问题，且系统已满足约定功能范围，可视为阶段验收通过。

## 十一、需求变更

合同签署后，任何新增功能、范围变化或已确认页面的大幅调整，应以书面形式确认。

需求变更应明确：

- 变更内容。
- 是否影响工期。
- 是否增加费用。
- 是否影响验收标准。

经双方确认后，乙方再开始执行变更内容。

以下事项通常视为新增需求：

- 新增模块。
- 新增角色或权限体系。
- 新增第三方系统对接。
- 新增复杂报表。
- 新增营销活动、会员、优惠券、发票等能力。
- 对已验收页面进行大幅视觉重做。
- 因甲方业务规则变化导致的数据结构或流程改造。
