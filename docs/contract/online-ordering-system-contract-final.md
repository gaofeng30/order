## 二、项目名称与合同定位

项目名称：在线点单系统开发服务。

项目定位：第一期 MVP 定制开发。

第一期目标：乙方为甲方交付一套可上线使用的微信小程序在线点单系统，覆盖用户点单、微信支付、线下自提、商户后台管理、订单核销和基础经营数据看板。

## 三、开发服务范围

### 3.1 用户端微信小程序

乙方应开发用户端微信小程序，第一期包含以下功能：

- 首页和门店基础信息展示。
- 菜品分类和菜品列表。
- 菜品详情、价格、图片、售罄状态展示。
- 购物车。
- 提交订单。
- 微信登录或手机号授权。
- 微信支付接入。
- 订单列表和订单详情。
- 订单号和二维码取餐凭证。
- 基础订单状态展示。
- 外卖入口 UI 预留，并明确标记“暂未开放”或同等含义提示。

### 3.2 商户管理后台

乙方应开发商户 Admin 后台，第一期包含以下功能：

- 后台登录。
- 商品分类管理。
- 商品管理。
- 商品图片上传。
- 商品价格、上下架、售罄状态管理。
- 订单列表和订单详情。
- 扫码核销和手动核销。
- 基础数据看板。
- 营业时间和公告配置。
- 基础后台权限控制。

### 3.3 后端服务与系统能力

乙方应开发后端服务和基础系统能力，第一期包含以下内容：

- API 服务。
- 数据库设计与实现。
- 用户、商品、分类、订单、支付、核销等核心数据模型。
- 订单编号和取餐码生成。
- 支付状态记录。
- 异常订单记录。
- 操作日志。
- 基础数据备份方案。
- 生产环境部署协助。

### 3.4 微信支付与上线协助

乙方应提供以下技术接入和配置协助：

- 微信小程序开发配置协助。
- 微信支付商户号接入协助。

- 域名、HTTPS、服务器部署配置协助。

甲方确认，微信小程序账号、微信支付商户号、云账号、域名、备案主体、收款账户和经营数据应归甲方所有。乙方不以个人主体长期代持甲方生产系统资产。

## 九、验收标准

项目验收以本合同第一期功能范围为准。

MVP 验收至少应满足以下标准：

- 用户可以在微信小程序完成浏览、加入购物车、提交订单。
- 用户可以完成微信支付或按双方确认的方式完成支付流程测试。
- 用户可以在订单详情看到订单号和二维码。
- 商户后台可以维护商品、价格、图片、上下架和售罄状态。
- 商户后台可以查看订单并完成扫码或手动核销。
- 系统可以正确处理基础订单状态变化。
- 数据看板可以展示今日营收、订单数和基础销量数据。
- 关键操作有日志，异常订单可追踪。

乙方提交验收版本后，甲方应在 `7 个工作日` 内完成验收并书面反馈问题。甲方提出的问题应限于本合同约定功能范围。若甲方未在期限内提出书面问题，且系统已满足本合同约定的主要功能范围，视为该阶段验收通过。

如验收中发现属于乙方开发原因导致的范围内功能缺陷，乙方应在合理期限内修复。超出本合同范围的新增要求，不影响已完成范围的验收。
