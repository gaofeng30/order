# 企业自营餐饮小程序资料准备简版清单

适用范围：企业自营餐饮小程序，当前包含点餐、到店自提、订单管理、在线支付；未来可能扩展外卖、快递、洗车等服务。

说明：小程序账号、微信支付商户号、域名、云账号、备案主体建议均归机构企业主体所有。个人开发者只作为开发和技术协作者参与。

## 一、机构需要提供

| 资料/信息 | 为什么需要 | 物料提供方式 | 完成状态 |
| --- | --- | --- | --- |
| 营业执照 | 用于小程序企业主体认证、小程序备案、微信支付商户号申请、餐饮类目资质核验。 | 提供清晰彩色扫描件或照片，确保企业名称、统一社会信用代码、经营范围、有效期完整可见。 |  |
| 统一社会信用代码 | 用于平台认证、备案、支付进件、合同主体确认。 | 可直接提供文字版，并与营业执照保持一致。 |  |
| 法定代表人身份证 | 用于微信认证、备案、支付进件、必要时的人脸或身份核验。 | 提供身份证正反面清晰彩色照片；如平台要求，法人需配合扫码、人脸、短信核验。 |  |
| 企业联系人信息 | 用于开发、审核、备案、支付、售后等流程中的日常沟通。 | 提供联系人姓名、手机号、微信、邮箱。 |  |
| 主体负责人/小程序负责人信息 | 小程序备案通常需要填写主体负责人和小程序负责人，并接收工信部短信核验。 | 提供姓名、身份证号、手机号、邮箱；负责人手机号需保持畅通。 |  |
| 公章配合 | 承诺函、授权书、资质说明、合同、平台补充材料可能需要盖章。 | 指定公章对接人，确认盖章流程和预计处理时间。 |  |
| 食品经营许可证 | 企业自营餐饮类目审核的核心资质。 | 提供清晰彩色扫描件或照片；证件主体、地址、经营项目需与实际门店和业务匹配。官方依据：[市场监管总局：食品经营许可和备案管理办法](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/fgs/art/2023/art_91a91c26ae464a2f898952d5b84f62c6.html)、[微信开放文档：餐饮服务类目资质](https://developers.weixin.qq.com/miniprogram/product/canyin/canyinfuwuchangsuo.html)。 |  |
| 门店基础信息 | 用于小程序展示、订单履约、用户到店自提、微信支付经营信息。 | 提供门店名称、地址、联系电话、营业时间、取餐地点。 |  |
| 门店照片 | 用于资质辅助、审核材料、产品页面和门店展示。 | 提供门头照、店内照、后厨/经营场所照，图片清晰无遮挡。 |  |
| 小程序名称备选 | 用于注册小程序，避免名称被占用或审核不通过。 | 提供 2-3 个名称备选，名称需与机构品牌或业务相关。 |  |
| 小程序简介 | 用于小程序资料页和审核。 | 提供一句话说明，例如“提供餐饮门店线上点餐、到店自提和会员服务”。 |  |
| 小程序管理员微信号 | 用于注册、认证、审核通知、权限管理。 | 提供管理员微信号和绑定手机号，管理员需能及时扫码确认。 |  |
| 微信支付商户号 | 用于小程序在线支付、退款、对账和结算。 | 如已有商户号，提供商户号和管理员对接方式；如没有，提供申请所需资料。 |  |
| 对公银行账户 | 用于微信支付商户号申请、结算、账户验证。 | 提供开户名、开户行、银行账号；开户名应与营业执照主体一致。 |  |
| 客服电话 | 微信支付、小程序展示、售后处理均可能需要。 | 提供可公开展示且能接通的客服电话。 |  |
| 菜品/商品清单 | 用于搭建菜单、分类、价格、库存、下单流程。 | 提供表格，包含分类、名称、价格、规格、口味、库存、是否上架。 |  |
| 菜品图片 | 用于小程序商品展示。 | 提供想要的风格/示例图，我们来AI生成。 |  |
| 退款/售后规则 | 用于订单取消、退款、用户投诉处理。 | 提供文字规则，例如支付后多久可取消、已出餐是否可退、退款由谁审核。 |  |
| 发票规则 | 用于订单和售后说明。 | 确认是否支持开票、开票类型、开票联系人。 |  |
| 后台账号角色 | 用于设计商户端权限。 | 提供老板、店长、店员、财务等角色，以及各自可操作范围。 |  |

## 二、开发者需要准备

| 准备项 | 为什么需要 | 交付/准备方式 | 完成状态 |
| --- | --- | --- | --- |
| 类目判断建议 | 避免把自营餐饮误报成外卖平台、多商户平台或快递服务，降低审核和资质风险。 | 当前建议按“企业自营餐饮门店点餐/自提”准备，未来扩展另行评估。官方依据：[微信开放文档：小程序开放的服务类目](https://developers.weixin.qq.com/miniprogram/product/material)、[微信开放文档：小程序备案服务内容标识选择指引](https://developers.weixin.qq.com/miniprogram/product/record/record_review.html)。 |  |
| 小程序账号注册指引 | 机构通常需要开发者协助完成注册、认证、授权。 | 给机构列出注册步骤、需要扫码的人、预计费用和时间。官方教程：[腾讯客服：小程序注册流程](https://kf.qq.com/faq/170109iQBJ3Q170109JbQfiu.html)、[微信开放文档：微信认证](https://developers.weixin.qq.com/miniprogram/product/renzheng.html)。 |  |
| 微信支付申请指引 | 在线支付依赖商户号、API 证书/密钥、回调地址。 | 指导机构申请或授权，开发者只接入机构商户号，不使用个人收款。官方教程：[腾讯客服：微信支付商户接入指引（电脑端）](https://kf.qq.com/faq/210423UrIRB7210423by6fQn.html)、[腾讯客服：微信支付商户接入指引（移动端）](https://kf.qq.com/faq/220211zQzQZR220211YBJvey.html)。 |  |
| 域名和备案建议 | 小程序后端必须使用 HTTPS 合法域名，中国大陆服务通常需要 ICP 备案。 | 建议机构用企业主体购买域名和云资源；开发者协助配置解析、证书、接口域名。官方教程：[腾讯云：ICP备案操作指引（PC端）](https://cloud.tencent.com/document/product/243/97666)、[腾讯云：备案域名相关](https://cloud.tencent.com/document/product/243/19627)、[阿里云：域名核验要求与准备指南](https://www.alibabacloud.com/help/zh/icp-filing/basic-icp-service/user-guide/prepare-and-check-the-domain-name)。 |  |
| 技术方案初稿 | 明确小程序端、后台、接口、数据库、支付、部署方式。 | 输出简要技术选型和环境规划，区分测试环境和生产环境。 |  |
| 产品功能范围 | 控制首期开发边界，避免未来外卖、快递、洗车混入首期交付。 | 明确首期只做餐饮自营点餐/自提/支付/后台管理，扩展功能进入二期。 |  |
| 合规提示 | 提醒机构哪些业务会触发额外资质。 | 对外卖平台、快递收派、洗车、储值卡、会员卡、配送等做风险备注。官方依据：[微信开放文档：外卖平台类目](https://developers.weixin.qq.com/miniprogram/product/canyin/waimaipingtai.html)、[市场监管总局：网络餐饮服务经营者规定](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/fgs/art/2026/art_d04d512f5ad8470eb61a652c0061dc3a.html)、[微信开放文档：收件/派件类目](https://developers.weixin.qq.com/miniprogram/product/kuaidi/jijianshoujian.html)、[交通运输部：机动车维修管理规定实施通知](https://xxgk.mot.gov.cn/2020/jigou/ysfws/202006/t20200623_3315961.html)、[商务部：单用途商业预付卡管理办法](https://www.mofcom.gov.cn/zfxxgk/zc/gz/art/2021/art_82805c1937a64a4186ea15c23fc675c5.html)。 |  |
| 验收标准 | 避免上线前责任不清。 | 为用户端、商户端、支付、退款、订单、后台权限分别列验收点。 |  |

## 三、当前建议

首期按“企业自营餐饮”推进，不在小程序描述、类目、页面文案中过早出现“快递服务、洗车服务”等表述。未来扩展时，再根据具体模式判断是否需要网络餐饮第三方平台备案、快递业务资质、洗车门店服务资质或其他专项材料。
