## 可直接纳入后续实现的缺陷修复

- **D01｜一次点击只执行一次操作**。表格在同一容器多次重绘后，`Table.bind` 不断新增监听，员工启停可能同时触发旧、新闭包，订单选行也会累积查询。每个容器仅保留当前事件代理；沿用现有菜品页替换容器的方法即可，不建立新框架。证据：`ui/table.js:40`；`pages/staff.js:61–85`；`pages/accounts.js:24–50`；`pages/orders.js:78–104`。这是代码路径判断，未运行复现。
- **D02｜旧请求不能关闭新弹窗**。抽屉／弹窗交给页面的是全局 `close`；保存 A 后关闭并打开 B，A 延迟返回可能关闭 B。把异步回调的关闭行为绑定到它自己的实例；不新增用户未批准的“提交时禁止关闭”。证据：`ui/drawer.js:27–34`、`ui/modal.js:21–27`。
- **D03｜确认弹窗取消必须完整结束**。点遮罩目前只移除弹窗，`confirm()` 的 Promise 不结束。遮罩及其他非确认退出按取消完成一次，避免未保存提醒的导航流程挂起；不增加 Esc。证据：`ui/modal.js:21–44`。
- **D04｜搜索结果与当前搜索词一致**。员工、商户账号搜索缺少请求顺序保护，旧请求晚返回时可能覆盖新结果。只接受最新查询结果，并排除已离开页面的回调；不自行把 P19 的 0.3 秒延迟扩展到其他页面。证据：`pages/staff.js:22,61`；`pages/accounts.js:20,25`。
- **D05｜导入文件与预览批次一一对应**。重新选择文件时立即撤下旧确认区；只有当前文件的预览响应可写回，取消或离页后旧响应不得重建结果。现有代码没有代次保护，文件 A 的迟到结果可覆盖文件 B。证据：`ui/import-flow.js:39–45,80`。
- **D06｜导入提交过程中保持批次稳定**。提交时显示进行中状态，限制换文件、取消重选等会替换当前批次的控件；完成或失败后恢复。现有 `state.busy` 仅拦确认按钮的处理函数，界面未同步体现，其他入口仍可改变当前状态。不得把旧批次完成回调写进新批次页面。证据：`ui/import-flow.js:72–92`。保留既有导入和异常行处理规则，不新增确认层。
- **D07｜菜品模板使用正确文件名**。菜品导入实际传入 `backRoute: 'products'`，下载逻辑却比较 `'product-import'`，导致下载名成为“员工白名单批量导入模板.xlsx”。修正名称判断，不改变模板列。证据：`pages/product-import.js:7`；`ui/import-flow.js:109`。
- **D08｜批量改价不接受空数值**。`Number('')` 会变成 0，百分比／增减模式可能在没有填写时仍提交并触发取整。先校验非空再计算；P8 的预览和提交使用同一计算结果。证据：`pages/products.js:214–223`。合法数值的现有取整规则暂不改变，见 C02。
- **D09｜批量改价先完整校验，再提交**。当前在循环内边检查边发请求，后一项价格非法时前面的请求可能已经发出。先算完并校验所有选中项，全部合法后才提交；网络阶段仍可能部分失败，按 P14 提醒并同步实际状态，不声称批量写入具有原子性。证据：`pages/products.js:218–229`。
- **D10｜编辑菜品保留当前隐藏分类**。分类下拉仅列出启用分类，导致编辑属于隐藏分类的菜品时当前分类消失。保留该菜品当前分类选项并标注隐藏状态，避免只补图／改描述时被迫换分类；不开放任意其他隐藏分类供新增选择。证据：`pages/products.js:237,266–270`。
- **D11｜图片上传提示符合实际能力**。菜品编辑写着“可直接拖拽”，实际只绑定点击选择。配合 P5 改成准确的选择图片说明，不扩展拖拽功能。多选超过剩余数量时明确提示最多 3 张及剩余可添加数，不能静默截掉而让用户误以为全已上传。证据：`pages/products.js:247,298–320`。
- **D12｜普通表单防止同一次保存重复发起**。分类的回车／点击、员工和商户账号的新增／保存补同一请求进行中的保护，失败保留输入并恢复；不新增确认弹窗，明确排除 P23 的折扣率保存。证据：`pages/categories.js:109–118`；`pages/staff.js:133–142`；`pages/accounts.js:106–116`。
- **D13｜刷新二维码后旧请求退出**。生成响应、轮询和过期提示均只作用于当前二维码；换码和离开登录页时清理旧定时器。注意旧轮询在 API 适配层就可能写入会话，不能只在页面绘制前加判断。证据：`app.js:234–262`；`data/api.js:148–153`。属于 P44 的完整实现，不改变登录期限与权限。
- **D14｜开屏拖动在中断后正确收尾**。补齐 `pointercancel`／失去指针捕获后的清理，明确拖动区域的触控行为，避免浏览器接管手势后遗留移动状态。响应式缩放时按实际画布与逻辑尺寸换算坐标，不能直接使用屏幕位移作为逻辑位移。证据：`pages/layer.js:257–281`。保留既有坐标存储与可调范围。
- **D15｜开屏图片加载失败不伪装为空画布**。当前图片 `onerror` 仅隐藏元素，保存的图层配置仍存在。显示局部图片不可用提示并保留换图入口与配置，避免商户对空白画布误判。证据：`pages/layer.js:37`。归入 P42/P43，不扩展为 P11 已拒绝的菜品列表状态改造。

## UI 细节与边缘精度检查点

- **V01｜设备宽度与外壳一起处理（P1）**。`index.html:5` 固定 `viewport width=1280`，`app.css:75` 同时设置 `body min-width:1280px`；只取消其中一项不能完成平板适配。侧栏、内容区、弹层与页面滚动边界必须一起调整。
- **V02｜侧栏首尾可达（P1）**。侧栏已有滚动能力，但 `app.css:127–128` 隐藏了滚动条，外壳又隐藏溢出。实现后看首尾菜单、品牌区与底部占位，不把“代码有 overflow”当作可达性证明。
- **V03｜固定多栏重排（P1）**。订单详情栏 372px、工作台右栏最小 300px、开屏控制栏最小 360px 都需随窄窗口重新排布，避免挤压主体。证据：`app.css:500,532,636`；工作台五列卡片还带行内列数，不能只改公共类。
- **V04｜弹窗与抽屉可视边界（P1）**。抽屉固定 480／720px，弹窗固定宽度且缺最大高度；限制在当前可视区域内，正文独立滚动，标题和底部动作可达。证据：`app.css:370–402`。
- **V05｜嵌套遮罩层级**。遮罩统一为 400，抽屉和弹窗同为 410；抽屉内打开确认弹窗时，新的遮罩仍位于抽屉下方，存在底层继续接收点击的风险。确认遮罩必须覆盖原抽屉，关闭确认只恢复原编辑界面。证据：`app.css:364,370,395`；`ui/modal.js:19–20`。实际点击表现待 UAT。
- **V06｜导入页失效颜色**。`--green-1`、`--green-2`、`--blue-2` 被引用但未定义，必填列描边和新增／更新数字样式可能失效。替换为现有且符合 P12 的语义色，不新增一套主题变量。证据：`app.css:777,783–784`。
- **V07｜禁用图标按钮要真正不可点**。现有禁用样式只覆盖 `.btn`，`.ibtn` 仍有手形和悬停高亮。落实 P13/P17/P29 时同步真实 `disabled`、视觉弱化及取消 hover/active；不能仅变灰。证据：`app.css:275,289–295`。
- **V08｜平板点击区域（P38）**。小按钮仅 28px 高，图标按钮 30px，开关 40×22px，图片删除按钮 20px。扩大交互区域和相邻间距，避免碰到相邻操作；视觉图标可保持小尺寸，不能只增加表格行高。证据：`app.css:285,290,451,588`。
- **V09｜长文字、号码、文件名**。处理无断点长订单号、长文件名、长错误和长地址：容器可收缩，必要时换行，不撑破表格或提示；复制仍使用完整值，图标不被压扁。证据：`app.css:407–423,478–481,780`。表格允许横向滚动，不把所有列都强行压成多行。
- **V10｜一套明确的字号层级（P37）**。清理行内 11.5／12.5／13.5px 等零散字号；标签、数值、按钮文字基线对齐。开屏模拟画面属于小程序示意内容，不机械套用 PC 后台字号。
- **V11｜表格圆角和滚动接缝（P39）**。实际观察表头两角、最末行两角、横向滚动条与外边框的交接；避免嵌套 `.tbl-wrap` 带来双描边、双圆角或重复滚动容器。证据：`ui/table.js:20,34` 与页面外层容器；`app.css:326–344`。当前仅列出结构风险，不宣称已肉眼复现。
- **V12｜边框精度（P39）**。统一同类控件描边，区分现有 1px 边框和 1.5px 内描边的用途；检查浏览器缩放下边缘清晰度，不用全局四舍五入坐标或改业务数值解决视觉问题。输入框聚焦前后尺寸不跳，选中态不得挤动邻项。
- **V13｜焦点状态可见**。开屏滑杆取消了 outline 却没有对应焦点样式，补可见 `focus-visible`；其他同类表单聚焦颜色随 P12 统一。证据：`app.css:442,730–734`。不增加 Esc 或关闭后自动回焦等 P45 未确认功能。
- **V14｜图片、价格和按钮稳定对齐（P5/P15/P38）**。占位图与实际缩略图占同一尺寸，加载完成不挤动文字；货币符号与数字基线一致，多行菜品信息不推挤右侧操作；不能把用于展示的格式化字符串重新送入金额计算。
- **V15｜错误提示的既有能力必须保留**。公共入口已有 `unhandledrejection` 转 Toast，不能把局部没有 catch 直接描述为“完全没有失败提示”。实施局部处理时避免重复弹两次，且不吞掉错误。证据：`app.js:208–212`。

## 开发前边界与确认状态

- **C01｜已确认纳入本轮：导入结果最小接口补充，待实现**。提交接口仅返回批次号与数量；预览只返回行号、结果、原因，未返回成功记录 ID、姓名／菜品名等结果展示所需数据。证据：`data/api.js:388–390`；`services/api/internal/importbatch/handler.go:140–151`。用户已同意为 P4/P25 增加最小的批次结果查询能力，返回记录 ID 与每条新增／更新结果，沿用现有权限与手机号脱敏规则。不能用全量列表前后差集或名称猜测“本次成功记录”。授权仅覆盖该接口补充，不扩大为其他后端需求或线上部署授权；实现前声明具体接口契约与 owned paths。
- **C02｜已确认：批量改价统一四舍五入到角**。用户明确保留角精度，固定价、百分比、加减金额三种方式均按角四舍五入，不改为分精度。P8 的预览与实际保存使用同一取整结果，三种方式的说明均写清精度。证据：`pages/products.js:208–223`；`data/api.js:178`。仍修复空输入与提交前完整校验；本决定限定于批量改价，不扩大到单菜编辑、员工折扣计算、历史订单或退款金额。
- **C03｜已确认：营业设置切换页面时提醒未保存，待实现**。现有 dirty 标记没有拦住侧栏切页，路由会直接清空并替换页面。证据：`pages/settings.js:102–107`；`app.js:171–200,214`。用户已单独确认：有未保存修改时切换到其他后台页面，提示「有未保存的修改，确定退出？」，按钮为「继续编辑 / 放弃修改」。继续编辑保留当前输入；放弃修改后离页且不提交；无修改或保存成功后离页不提示。此项补充 P28 的重新载入提醒，不改变现有保存结果不确定时的核对规则。
- **历史依赖仍保持边界**：此前小程序 B1–B5、PC 图片压缩等未纳入本轮的需求，不因这次审阅自动加入。P27 是用户本轮明确新增的可编辑取餐地点要求；当前后端已有对应保存代码，不据此直接修改线上地点。
