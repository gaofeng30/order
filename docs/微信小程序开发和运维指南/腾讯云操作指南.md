# 腾讯云生产资源开通与运维指南

> 适用范围：政府/企业食堂在线点单系统一期，500 人以内、短时集中点单。
> 本指南是客户采购与责任视图；组件、数据流和运行边界以 [`在线点单系统技术文档`](../product/online-ordering-system-technical.md) 的生产架构基线为准。
> 甲方持有企业云账号、域名、微信身份、支付商户号、资产与费用责任；乙方在获授权范围内完成配置、部署协助、联调与技术运维。本 change 不购买、配置、部署或探测任何真实资源。

## 1. 唯一采购基线

一期只开通以下生产能力，不再保留平台选型分支：

| 能力 | 固定组件 | 固定边界 |
| --- | --- | --- |
| 计算与 HTTPS | 单台中国境内 CVM，Nginx + systemd + Go/Gin `order-api` 与同进程 worker | Nginx `:443` 终止 TLS，`:80` 只跳转 HTTPS，反向代理至 `127.0.0.1:8080` |
| 交易数据库 | TencentDB MySQL 8.0 双节点、多可用区、一主一备 | 与 CVM 同地域，只允许生产 CVM 内网访问；MySQL 是应用业务事实源 |
| 商品图片 | 同地域私有 COS | 禁止匿名读取和列举；使用预签名 PUT、预签名 GET；开启版本控制 |
| 配置与密钥 | systemd EnvironmentFile + SSM + CVM CAM Role | 非敏感配置与密钥分离；角色只能读取本环境 SSM 前缀 |
| 日志与监控 | CLS + LogListener、云监控、CAT | 脱敏 JSON 日志、固定指标/告警、公网可用性探测 |
| 域名与证书 | 甲方企业域名、ICP备案、HTTPS 证书 | UAT 与生产域名/证书/回调地址隔离 |

架构不包含 Kubernetes、微服务、Redis、MQ、读写分离、数据库代理、CLB、CDN、跨地域灾备或 7×24 人工值守。增加这些组件必须由技术文档中的真实容量或 RTO 失败证据触发，并另建 OpenSpec change。

## 3. 开通顺序与责任

### 3.1 企业账号、域名和合规

1. 甲方使用企业主体注册腾讯云账号并完成企业实名认证；主账号不得交付给乙方。
2. 甲方持有域名与备案主体；操作见 [`域名操作指南`](./域名操作指南.md) 与 [`ICP备案操作指南`](./ICP备案操作指南.md)。
3. 甲方开通最小权限 CAM 子账号或授权角色；乙方不要求常驻主账号权限。
4. UAT 与生产使用不同域名、证书、小程序 AppID 和回调地址。

境内公网服务上线前完成备案与 HTTPS。参考：[ICP备案](https://cloud.tencent.com/document/product/243/18908)、[SSL 证书与 Nginx](https://cloud.tencent.com.cn/document/product/400/35244)（访问日期：2026-08-13）。

### 3.2 网络与 CVM

1. 在 `TODO_TENCENT_REGION` 规划 UAT 与 prod 独立 VPC；资源清单记为 `TODO_VPC_ID`。
2. 分别购买 `TODO_UAT_CVM_INSTANCE_TYPE` 与 `TODO_PROD_CVM_INSTANCE_TYPE`；规格必须在隔离环境通过容量门后才能称为可用。
3. 生产只部署一台 CVM。公网安全组只开放业务 HTTPS 与受限运维入口；应用监听地址不得直接暴露公网。
4. 乙方配置 Nginx、systemd、`order-api`、同进程 worker、LogListener 和 readiness 检查。

CVM 丢失的 RTO ≤60 分钟只是未实测目标；恢复依赖发布物、Nginx/systemd 配置、SSM 和重建 runbook，不依赖 CVM 本地业务数据。

### 3.3 TencentDB MySQL 8.0

1. UAT 与 prod 分别创建独立 CDB 实例，选择 TencentDB MySQL 8.0 双节点、多可用区、一主一备形态。
2. UAT 使用 `TODO_UAT_CDB_INSTANCE_TYPE`，prod 使用 `TODO_PROD_CDB_INSTANCE_TYPE`；两者引擎版本一致。
3. CDB 与对应 CVM 同地域，仅允许对应环境 CVM 内网访问，不开放公网。
4. 开启每日全量备份；数据备份和 binlog 保留 14 天，实例销毁后的备份保留 7 天。
5. 破坏性 migration 前创建手动备份；每季度恢复或克隆到隔离实例，校验 schema、订单、支付、退款、核销和操作日志。

数据库迁移由部署前独立命令 `order-migrate` 执行：forward-only SQL、`schema_migrations` 与 `GET_LOCK` 共同防止重复/并发迁移；`/health/ready` 必须检查数据库和 schema version，生产不自动 down。

Go 进程/CDB 主备故障 RTO ≤5 分钟、逻辑损坏 RPO ≤5 分钟与 RTO ≤2 小时均为未实测目标；区域级灾难在本阶段不承诺 RPO/RTO。参考：[双节点高可用](https://cloud.tencent.com/document/product/236/47906)、[自动备份与 binlog](https://cloud.tencent.com/document/product/236/35172)、[时间点恢复](https://cloud.tencent.com/document/product/236/7276)（访问日期：2026-08-13）。

### 3.4 私有 COS

1. 在 `TODO_TENCENT_REGION` 创建 `TODO_UAT_COS_BUCKET` 与 `TODO_PROD_COS_BUCKET` 两个独立私有桶，禁止匿名读取与列举。
2. 开启版本控制；非当前版本 30 天后删除。
3. Admin 先向 API 申请不超过 15 分钟的预签名 PUT，由服务端生成 object key 并限制 MIME、大小与摘要；上传后调用确认接口。
4. 已授权客户端通过不超过 15 分钟的预签名 GET 读取图片；MySQL 只保存 object key 与元数据。
5. 不交付长期 SecretId/SecretKey；CVM 通过 CAM Role 临时身份访问本环境桶。

参考：[COS 安全基线](https://cloud.tencent.com/document/product/436/50200)、[预签名请求](https://cloud.tencent.com/document/product/436/14114)（访问日期：2026-08-13）。

### 3.5 SSM、CAM 与运行配置

- 非敏感配置写入 root-owned、权限不宽于 `0640` 的 systemd EnvironmentFile。
- SSM SecretName 唯一采用 `order-{env}-{purpose}`；当前只创建 `db-password` 与 `wechat-miniprogram-app-secret`，production 对应 `order-production-db-password` 与 `order-production-wechat-miniprogram-app-secret`，不创建兼容别名或未使用的未来 Secret。
- UAT 与 prod 使用不同 CAM Role；每个角色只能对本环境上述两个 Secret 执行 `ssm:GetSecretValue`，并按既有边界访问本环境私有 COS。
- 应用只使用 CVM instance role 临时凭据；启动读取必要密钥失败时必须失败，不回退到环境/配置文件中的长期 SecretId/SecretKey、本地 Secret 文件、命令行或内置值。
- 密钥轮换由甲方授权管理员更新 `SSM_Current`，乙方按变更窗口重启进程加载；正文不记录敏感值。新增 purpose 必须由实现它的独立 change 同步更新固定 allowlist。

参考：[SSM](https://cloud.tencent.com/document/product/1140/40416)、[CAM Role](https://cloud.tencent.com/document/product/598/19421)（访问日期：2026-08-13）。

### 3.6 CLS、云监控与 CAT

乙方配置 `order-api` 向 stderr 输出脱敏 JSON，LogListener 采集到 CLS 并保留 30 天。日志不得包含 query、body、Authorization、Cookie、个人信息、回调原文、完整外部交易号或凭据。

固定告警条件如下：

| 信号 | 条件 |
| --- | --- |
| CAT | 每分钟公网探测一次，连续 3 次失败 |
| HTTP | 5 分钟 5xx `>1%`；读取 p95 `>500ms` 或写入 p95 `>800ms` 持续 5 分钟 |
| 异步 | 最老 `inbox_events`/`outbox_events` `>60 秒`；任一 `DEAD` 立即告警 |
| 交易/备份 | 任一支付对账不一致或备份失败立即告警 |
| CVM | CPU `>70%` 持续 15 分钟；内存 `>80%`；磁盘 `>75%` |
| CDB | CPU 或连接使用率 `>70%` 持续 15 分钟；存储 `>75%` |
| TLS | 证书剩余有效期 `<30 天` |

告警接收清单为 `TODO_ALERT_RECIPIENTS`。告警全天发送，不构成 7×24 人工值守承诺。参考：[CLS](https://cloud.tencent.com/document/product/614/56479)、[LogListener](https://cloud.tencent.com/document/product/614/17415)、[云监控](https://cloud.tencent.com/document/product/248/62458)、[CAT](https://cloud.tencent.com/document/product/280)（访问日期：2026-08-13）。

## 4. 环境隔离与部署

| 环境 | 必须独立的资源和身份 |
| --- | --- |
| dev | 开发配置、数据库、私有测试桶、微信 stub/开发身份 |
| UAT | VPC、CVM、CDB、私有 COS、域名、证书、SSM 前缀、CAM Role、微信身份 |
| prod | VPC、CVM、CDB、私有 COS、域名、证书、SSM 前缀、CAM Role、微信身份 |

生产数据不得原样进入 dev/UAT；需要样本时先做不可逆匿名化。单个进程只绑定一个环境，不得同时访问两个环境。

生产发布顺序固定为：

1. 仅在破坏性 migration 前确认手动备份。
2. 执行 `order-migrate`。
3. 启动或重启 systemd `order-api` 单元。
4. 验证 `/health/ready` 的 DB 与 schema 检查。
5. 验证 CAT、CLS、云监控与关键告警接收。

本指南不执行上述步骤；实际部署需要独立获批 change。

## 5. 容量验收与升级条件

生产候选规格在隔离环境完成以下未实测容量门后，才能确认购买规格满足一期：200 并发、300 单/5 分钟、至少 1000 日订单与 300 商品，同时覆盖重复提交、重复/乱序微信回调、worker 重启和未支付超时并发。目标为 HTTP 5xx `<0.1%`、读取 p95 `≤500ms`、写入 p95 `≤800ms`，且交易、`inbox_events`、`outbox_events` 与库存不变量无重复或丢失。

失败后的升级顺序固定为：先修复慢 SQL、索引、连接池与非必要查询；再纵向升级 CVM/CDB；重跑同一容量门后仍失败，才按技术文档的证据条件创建独立扩展 change。未经实测不得预先加入额外运行组件。

## 7. 安全交接清单

甲方只提供资源标识与最小授权，不在聊天、邮件、文档、代码或前端配置中传递敏感正文。乙方需要的最小信息为第二节的命名外部值，以及由甲方在控制台完成的 CAM Role 授权。

以下内容不得交付或入库：主账号密码、CVM 登录凭据正文、数据库密码、长期访问 key、微信商户私钥、APIv3 key、证书正文、回调报文、个人信息。排障授权必须限时、最小权限并保留审计；收款主体和经营责任始终属于甲方。

微信支付平台操作见 [`微信支付操作指南`](./微信支付操作指南.md)。回调实现必须先验签、解密、唯一 inbox 持久，再在总计 5 秒内应答；业务事务产生 `outbox_events`，同进程 worker 使用 `SKIP LOCKED`、lease、at-least-once 与幂等消费，第 10 次失败进入 `DEAD` 并告警。参考：[微信支付回调](https://pay.wechatpay.cn/doc/v3/merchant/4012791861)（访问日期：2026-08-13）。
