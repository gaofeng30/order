## 订单发货管理

- 不开通旧的“购物订单”：该功能已停止维护。
- 当前能力是“小程序发货信息管理/交易结算管理”。
- 因服务类目尚未设置，目前不能确认该账号是否已被平台纳入发货管理。
- 类目通过后，通过关联商户详情或 `is_trade_managed` 接口确认：
  - 返回未纳管：记录证据，不新增接入。
  - 返回已纳管：后端必须接入 `upload_shipping_info` 和订单状态查询。
- 到店自提被纳管时：`logistics_type=4`（用户自提）、`delivery_mode=1`（统一发货）；建议在顾客实际取餐/订单完成时上报，不在支付成功时提前上报。
- 小程序消息推送 URL 不是首轮支付 E2E 的硬前置；它与微信支付 APIv3 支付回调是两套独立配置。

## 明确不需要配置

- 微信支付 APIv2 密钥
- 小程序支付的 JSAPI 授权目录
- 已停止维护的“购物订单”功能
- 配送物流插件：一期仅到店自提，不含配送
- App 支付、虚拟支付、服务商模式

## 执行顺序

1. 小程序管理员补服务类目。
2. 微信支付超级管理员完成 API 安全和小程序经营场景。
3. 小程序管理员完成备案、生成 AppSecret、添加体验成员。
4. 开发方完成 HTTPS 后端、服务器域名、密钥管理和回调部署。
5. 开通两类订阅消息，完成隐私与手机号配置。
6. 判断是否被纳入订单发货管理；如被纳管，完成自提履约上报。
7. 上传体验版并进行真机 E2E。
8. E2E 通过后提交审核，审核通过后由客户确认发布。

## E2E 验收条件

- [ ] 新用户可免手机号浏览商品。
- [ ] 首次结算可完成微信会话和手机号授权。
- [ ] 可创建预支付并调起微信支付。
- [ ] 仅服务端确认支付成功后生成订单。
- [ ] 支付回调、主动查单和重复通知均保持幂等。
- [ ] 门店可推进制作、备好、取餐核销和订单完成。
- [ ] 用户授权后可收到待取餐提醒。
- [ ] 取消订单可原路全额退款并收到退款结果通知。
- [ ] 如账号被纳管，自提订单履约信息上报并可查询成功。
- [ ] 体验版真机完整跑通，无域名、权限、支付或隐私报错。
- [ ] 小程序审核通过，客户确认后发布。
